# 快速开始

本文以本地 Docker Compose 为主路径，帮助你启动 NexusAuth Provider、Workbench API 和 Dashboard。生产部署前请继续阅读 [环境准备](./02-环境准备.md)、[启动 NexusAuth Provider](./04-启动NexusAuth.Provider.md) 和 [配置 OAuth 客户端](./05-配置OAuth客户端.md)。

## 前置要求

- Git
- Docker Engine 和 Docker Compose v2（`docker compose` 命令）
- 使用本地进程启动时，还需要 .NET 10 SDK、Node.js 20+ 和 PostgreSQL 16+

## 方式一：Docker Compose

### 1. 获取代码

```bash
git clone https://github.com/KawhiWei/NexusAuth.git
cd NexusAuth
```

### 2. 设置本地配置

Compose 会从当前 shell 或项目根目录的 `.env` 文件读取变量。下面的值适合本地测试，请替换密码和客户端密钥：

```bash
export POSTGRES_USER=nexusauth
export POSTGRES_PASSWORD='REPLACE_WITH_DATABASE_PASSWORD'
export WORKBENCH_CLIENT_SECRET='REPLACE_WITH_WORKBENCH_CLIENT_SECRET'
export NEXUSAUTH_BOOTSTRAP_ADMIN_USERNAME=admin
export NEXUSAUTH_BOOTSTRAP_ADMIN_PASSWORD='REPLACE_WITH_ADMIN_PASSWORD'
export NEXUSAUTH_BOOTSTRAP_ADMIN_NICKNAME='System Admin'
export NEXUSAUTH_BOOTSTRAP_ADMIN_EMAIL='admin@example.com'

# 登录页“3 天内免登录”的默认值就是 3；可改为 1-30 的整数。
export NEXUSAUTH_LOGIN_FLOW_REMEMBER_ME_LIFETIME_DAYS=3
```

`NEXUSAUTH_*` 是 Provider 和 Workbench API 的单下划线环境变量命名。Compose 会将它们映射到对应的 .NET 配置节。不要把真实 Secret、证书密码或私钥提交到仓库。

### 3. 构建并启动

```bash
docker compose up -d --build
docker compose ps
```

启动完成后访问：

| 服务 | 地址 |
|------|------|
| NexusAuth Provider | http://localhost:5100 |
| Workbench API | http://localhost:5051/swagger |
| Workbench Dashboard | http://localhost:5273 |

Compose 在全新的数据库数据卷首次启动时会依次执行：

1. `production-init.sql`，创建 `nexusauth` schema 和全部表；
2. `admin/src/NexusAuth.Workbench.Api/seed.sql`，登记 Workbench 所需的 API resource 和 OAuth client；
3. 本地 SCIM 集成测试凭据的初始化。

初始管理员由 SSO 容器启动时读取 `NEXUSAUTH_BOOTSTRAP_ADMIN_*` 创建。用户名或密码只配置其中一个会导致 Provider 启动失败；用户名已存在时会保留原密码，不会被环境变量覆盖。Compose 文件中的默认管理员和默认密钥仅用于开发环境，生产必须显式覆盖。

### 4. 登录 Dashboard

使用上一步设置的管理员账号访问 http://localhost:5273。首次登录时，Provider 登录页默认显示“3 天内免登录”。勾选后，登录 Cookie 和服务端 SSO 会话在配置的固定期限后同时失效，不会因持续访问而延长。修改 `NEXUSAUTH_LOGIN_FLOW_REMEMBER_ME_LIFETIME_DAYS` 后需要重新创建或重启 SSO 容器；已经签发的 Cookie 不会被新值延长。

### 5. 查看日志和停止服务

```bash
docker compose logs -f sso
docker compose logs -f admin-api
docker compose down
```

`docker compose down` 不会删除数据库数据卷。只有确认不再需要本地数据时才执行：

```bash
docker compose down -v
```

该命令会删除 Compose 管理的数据库数据，下一次启动才会重新执行数据库初始化脚本。`production-init.sql` 只面向全新数据库，不是历史数据库升级脚本。

## 方式二：本地进程启动

### 1. 启动 PostgreSQL 并初始化空库

```bash
docker run -d \
  --name nexusauth-db \
  -e POSTGRES_PASSWORD=REPLACE_WITH_DATABASE_PASSWORD \
  -e POSTGRES_USER=nexusauth \
  -e POSTGRES_DB=nexusauth \
  -p 5432:5432 \
  postgres:16
```

等待数据库就绪后，在仓库根目录执行：

```bash
psql -h localhost -U nexusauth -d nexusauth -v ON_ERROR_STOP=1 -f production-init.sql
```

Workbench seed 使用未限定 schema 的表名，需要在同一 psql 会话中先设置 `search_path`：

```bash
psql -h localhost -U nexusauth -d nexusauth -v ON_ERROR_STOP=1 <<'SQL'
SET search_path TO nexusauth;
\i admin/src/NexusAuth.Workbench.Api/seed.sql
SQL
```

`production-init.sql` 不创建默认用户，也不执行 `demo/seed.sql`。Workbench API 首次启动时会根据 `Auth:ClientSecret` 为已 seed 的 `nexusauth.workbench` 客户端创建或同步共享密钥。

### 2. 启动 Provider

```bash
export NEXUSAUTH_CONNECTION_STRINGS_DEFAULT='Host=localhost;Port=5432;Database=nexusauth;Username=nexusauth;Password=REPLACE_WITH_DATABASE_PASSWORD;Search Path=nexusauth'
export NEXUSAUTH_JWT_ISSUER='http://localhost:5100'
export NEXUSAUTH_BOOTSTRAP_ADMIN_USERNAME=admin
export NEXUSAUTH_BOOTSTRAP_ADMIN_PASSWORD='REPLACE_WITH_ADMIN_PASSWORD'

dotnet run --project src/NexusAuth.Host
```

Provider 默认监听 http://localhost:5100。开发环境会自动生成并持久化 JWT 开发签名证书；生产环境必须预置受管签名证书，详见 [启动 NexusAuth Provider](./04-启动NexusAuth.Provider.md)。

### 3. 启动 Workbench API 和 Dashboard

打开新的终端，在仓库根目录设置 Workbench API 的数据库、客户端密钥和 API audience：

```bash
export NEXUSAUTH_WORKBENCH_CONNECTION_STRINGS_DEFAULT='Host=localhost;Port=5432;Database=nexusauth;Username=nexusauth;Password=REPLACE_WITH_DATABASE_PASSWORD;Search Path=nexusauth'
export NEXUSAUTH_WORKBENCH_AUTH_CLIENT_SECRET='REPLACE_WITH_WORKBENCH_CLIENT_SECRET'
export NEXUSAUTH_WORKBENCH_AUTH_AUDIENCE=workbench

dotnet run --project admin/src/NexusAuth.Workbench.Api
```

再打开一个终端启动 Dashboard：

```bash
npm --prefix admin/src/NexusAuth.Workbench.Dashboard install
npm --prefix admin/src/NexusAuth.Workbench.Dashboard run dev
```

Dashboard 开发服务器监听 http://localhost:5273，并将 `/api` 请求代理到 http://localhost:5051。Workbench API 的 OIDC 回调地址是 `http://localhost:5051/signin-oidc`，回调完成后会把浏览器带回 Dashboard 的 `/auth/callback`。
