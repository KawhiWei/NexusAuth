# 环境准备

本文列出本地运行 NexusAuth 所需的软件、目录和端口。仓库使用 .NET 10；使用 Docker Compose 时，Provider、Workbench API、Dashboard 和 PostgreSQL 都由 Compose 管理。

## 软件要求

| 软件 | 版本 | 用途 |
|------|------|------|
| .NET SDK | 10.0 | Provider 和 Workbench API |
| Node.js | 20.x 或更高 | Dashboard 开发和构建 |
| npm | 随 Node.js 安装 | Dashboard 依赖管理 |
| PostgreSQL | 16.x | 持久化数据库 |
| Docker Engine | 支持 Compose v2 | 推荐的本地一键启动方式 |
| Git | 2.x 或更高 | 获取源代码 |

生产部署还需要 HTTPS 终止代理、受管的 JWT 签名证书或 RSA 签名密钥，以及安全的 Secret 存储。开发环境可以使用 Provider 自动生成的签名证书。

## 检查安装

```bash
dotnet --version
# 应输出 10.0.x

node --version
# 应输出 v20.x 或更高

npm --version

psql --version
# 应输出 PostgreSQL 16.x

docker compose version
```

## 获取代码

```bash
git clone https://github.com/KawhiWei/NexusAuth.git
cd NexusAuth
```

## 目录结构

```text
NexusAuth/
├── src/
│   ├── NexusAuth.Host/             # OAuth/OIDC Provider
│   ├── NexusAuth.Domain/           # 领域模型
│   ├── NexusAuth.Persistence/      # PostgreSQL 数据访问
│   ├── NexusAuth.Application/      # 应用服务
│   └── NexusAuth.Shared/           # 共享基础设施
├── admin/
│   ├── NexusAuth.Admin.sln         # Workbench API 解决方案
│   └── src/
│       ├── NexusAuth.Workbench.Api/       # Workbench BFF/API
│       ├── NexusAuth.Workbench.Dashboard/ # React + Vite 前端
│       └── NexusAuth.Extension/           # OIDC 集成扩展
├── demo/                           # OAuth/OIDC 示例客户端
├── document/                       # 中文文档
├── docker/                         # PostgreSQL Compose 初始化脚本
├── docker-compose.yml
└── production-init.sql             # 全新数据库的最终 schema
```

共享的 Domain、Application、Persistence 和 Shared 项目位于根目录 `src/`，不要在 `admin/` 下复制一份。

## 默认地址和端口

| 服务 | 本地地址 | 配置来源 |
|------|----------|----------|
| NexusAuth Provider | http://localhost:5100 | `src/NexusAuth.Host/Properties/launchSettings.json` |
| Workbench API | http://localhost:5051 | `admin/src/NexusAuth.Workbench.Api/Properties/launchSettings.json` |
| Workbench Dashboard（开发） | http://localhost:5273 | `admin/src/NexusAuth.Workbench.Dashboard/vite.config.ts` |
| Workbench Dashboard（Compose） | http://localhost:5273 | Compose 映射到 nginx 80 端口 |
| PostgreSQL | localhost:5432 | Docker 或外部 PostgreSQL 配置 |

Dashboard 开发服务器把 `/api` 代理到 Workbench API 的 5051 端口。Compose 中 Dashboard nginx 将同一路径代理到容器内的 `admin-api:8080`，浏览器仍然只访问 5273。

## PostgreSQL 要求

Provider 和 Workbench API 共用一个数据库，默认数据库名为 `nexusauth`，默认 schema 为 `nexusauth`。`production-init.sql` 会创建 `pgcrypto` 扩展、schema 和当前全部表，但不会创建数据库本身。

新库必须先由数据库平台创建，再执行 [production-init.sql](../production-init.sql)。Compose 的 `docker/postgres-init.sh` 会在全新数据卷中创建数据库并自动执行该脚本；初始化脚本不会在已有数据卷上再次运行。

## 环境变量命名

Provider 和 Workbench API 使用仓库自定义的单下划线变量映射，便于在 Docker、Kubernetes 等环境中统一配置：

```text
NEXUSAUTH_CONNECTION_STRINGS_DEFAULT
NEXUSAUTH_JWT_ISSUER
NEXUSAUTH_LOGIN_FLOW_REMEMBER_ME_LIFETIME_DAYS
NEXUSAUTH_BOOTSTRAP_ADMIN_USERNAME
NEXUSAUTH_WORKBENCH_AUTH_CLIENT_ID
NEXUSAUTH_WORKBENCH_AUTH_CLIENT_SECRET
```

完整映射以 `src/NexusAuth.Host/Program.cs` 和 `admin/src/NexusAuth.Workbench.Api/Program.cs` 为准。登录页的免登录期限默认为 3 天，允许 1-30 天；修改后需要重启 Provider。

## 本地构建检查

在仓库根目录执行：

```bash
dotnet build NexusAuth.sln
dotnet build admin/NexusAuth.Admin.sln
npm --prefix admin/src/NexusAuth.Workbench.Dashboard install
npm --prefix admin/src/NexusAuth.Workbench.Dashboard run build
```
